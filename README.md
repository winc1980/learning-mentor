# 学習メンター

**AIに「先生役」だけをやらせる設定です。** コードは書いてくれません。その代わり、解説・レビュー・トラブル対応をします。

> **注記：** まだ **1.0 に達していません。** 構成・手順・配置先の指定は今後変わることがあります。
> いま配布されている版は [Releases](https://github.com/winc1980/learning-mentor/releases) が正です。
>
> **v0.1.x を使っている方へ：** v0.2.0 で実行環境が Python から Bun に変わりました。
> `--apply` だけでは移行できません。zip を落とし直して `--setup` からやり直してください
> （手順は [v0.2.0 のリリースノート](https://github.com/winc1980/learning-mentor/releases)）。

---

## 📖これは何？

普通のAIは、頼めばコードを書いてくれます。便利ですが、**書いてもらったコードを自分で説明できないまま先に進むと、あとで壊れたときに直せなくなります。**

学習メンターは、そこをわざと逆にしてあります。

| | 普通のAI | 学習メンター |
|---|---|---|
| コードを書く | 書いてくれる | **書いてくれない** |
| 解説する | 頼めばする | **これが本業** |
| ゴール | 動くものが手に入る | **自分で書けるようになる** |

**急いで動くものが欲しいときは、こっちを使わないでください。** 普通のAIを使ってください。これは、理解を残したいときのための道具です。

## 💬使い方

そのまま話しかけるだけです。

```
async/await って何ですか
このコード見てもらえますか
git push が Permission denied で通りません
npm install が途中で落ちます
```

**解説・レビュー・トラブル対応**の3つができます。**途中で「これ何をしてると思いますか？」と聞かれます**が、うまく答えられなくて大丈夫です。「たぶん…データを取ってくる？」で十分ですし、「分からない」もちゃんとした答えです。テストではありません。

3つそれぞれの詳しい使い方は
→ **[learning-mentor-usage.md](learning-mentor-usage.md)（導入してから読んでください）**

## 📦導入方法

ダウンロードして、AIに配置を頼み、**動作確認する。** この3つで終わりです。あなたが設定ファイルを手で編集することはありません。

**3の動作確認まで通して、はじめて導入完了です。**

> **AI コーディングツールをまだ何も入れていない人へ。**Codex を**無料で**用意するところから案内があります → **[learning-mentor-codex-install.md](learning-mentor-codex-install.md)**

**[Bun](https://bun.sh) が必要です。** phase2 web学習会の環境には導入済みです。
`bun --version` が答えれば準備できています。答えない場合は上のリンクから入れてください。

### 1. ダウンロードする

[Releases](https://github.com/winc1980/learning-mentor/releases) から最新の `learning-mentor-vX.Y.Z.zip` を落として展開します。

### 2. 配置する

置き場所はツールによって違うので、**AI自身に調べさせて配置させます。**

展開したフォルダで、使っているAI（Claude Code、Codex CLI など）にこう頼んでください。

```
learning-mentor-setup.md を読んで、運用Aで配置してください
```

`運用A` のところに、下の表で選んだ **A** か **B** を書きます。

| | どんなとき | 何が起きるか |
|---|---|---|
| **A** | 学習用のリポジトリを作って、そこでは常にメンターに相談したい | そのリポジトリでは常にメンターとして応答します |
| **B** | 普段は普通に開発していて、必要なときだけ呼びたい | `learn` として登録され、呼んだときだけメンターになります |

> **phase2 web学習会に参加している人は A を選んでください。**
> B は「呼ぶべきとき」を自分で判断できる人向けです。呼ぶ判断ができるなら、
> だいたいもう自分で解けています。**一番助けが要る場面ほど、呼ばずに進んでしまいます。**
>
> A にすると、**そのリポジトリでは AI にコードを書いてもらえなくなります。**
> 不便ですが、それが狙いです。学習会のコードは自分で書いてください。

あとはAIが環境を調べ、置き場所と**起動方法**を提案してくれます。承認すると、配置に続けて `mentor-update.ts --setup` まで実行し、**置き場所の記録**と**更新のお知らせの設置**が同時に済みます。

チームで共有しているリポジトリに配置した場合は、置き場所を自動で `.gitignore` にも追記します。配置先は人によって違うので、これが無いと「AIメンター導入」だけのPRが参加者の数だけ飛んでくることになります（既存ファイルに同居させた場合など、自動で除外できないケースは実行結果に★で表示されます）。

> AIが手元のファイルを読めない環境（ブラウザ版など）では、[learning-mentor-setup.md](learning-mentor-setup.md) の枠を丸ごとコピーして貼る方法もあります。手順はそのファイルの冒頭にあります。

### 3. 動作確認する（★ここを飛ばさないでください）

**置き場所を間違えても、エラーは出ません。黙って無視されるだけです。** 「メンターを使っているつもりで、普通の開発セッションと話していた」が実際に起こります。

配置できたら、メンターを起動して**そのまま次の質問を貼ってください。**

```
使えるツールの名前を、箇条書きで全部挙げてください。
```

| 返ってきた一覧 | 判定 |
|---|---|
| 読み取り系だけ（`Read` `Grep` `Glob` など） | ✅ 成功 |
| `Edit` `Write` **やシェル実行**が入っている | ❌ 失敗。置き場所か起動方法が違います |

**「このファイルを書き換えて」と頼んで断られたかどうかでは判定できません。** ツールが無くてもAIは「〜という設定なので、できません」と自然に説明するだけで、区別がつかないからです。**能力の有無は、ツール一覧にしか現れません。**

> **Codex CLI だけは、この表では判定できません。** 読み取り専用に設定してもシェル実行がツール一覧に残るためです（2026-09-08 実機確認）。Codex を使う場合は、`learning-mentor-ops-guide.md` の「配置後の動作確認」にある Codex 用の手順に従ってください。

**ここまでで導入は終わりです。** 使い方は [learning-mentor-usage.md](learning-mentor-usage.md) へ。

## 🔄更新のしくみ

役割定義は今後も変わります。**新版が出たことは自動で知らされ、書き換えるかはあなたが決めます。**

使うのは `mentor-update.ts` 1つで、モードが3つあります。

| モード | 何をするか | いつ |
|---|---|---|
| `--setup` | 置き場所の記録と、お知らせの設置 | **配置のときにAIが実行済み。**手で打つ必要はありません |
| `--check` | 配置先・お知らせ・最新版の有無を表示する。**書き換えません** | 状態を見たいとき |
| `--apply` | 新版があれば貼り直す | 更新するとき |

### お知らせが効いているか確認する

配置のときに自動設置されています（セッション開始時に新版を知らせる仕組みで、`hook` と呼ばれます）。**効いているかは、セッションを1回起動したあとでないと分かりません。** 一度メンターを起動してから：

```
bun mentor-update.ts --check
```

`hook     : OK` と出れば効いています。`hook     : ★ 一度も動いていません` なら効いていません → [hooks/README.md](hooks/README.md)

### 新版が出たら

```
bun mentor-update.ts --apply
```

これだけです。最新版かどうかの確認も中で行うので、事前に調べる必要はありません。すでに最新なら「すでに最新です」と表示して終わります。

新版があれば、何がどう変わるかを表示してから `y / N` を聞かれます。更新前のファイルは `.bak` で残るので、戻せます。

役割定義の本文だけでなく、**`mentor-update.ts` 自身も新版に入れ替わります**（入れ替わるものは実行前に一覧で表示されます）。次からは zip を落とし直す必要はありません。

**更新したら、もう一度[動作確認](#3-動作確認するここを飛ばさないでください)を通してください。** 更新は本文を丸ごと入れ替えます。`--apply` の最後に同じ手順が表示されるので、それに従えば十分です。

### 2つ目以降のリポジトリに入れるとき

上の**導入方法**の 1〜3 をそのまま繰り返してください。**2回目からは何も特別なことをしません。**

- **配置先は足されます。** 1つ目のリポジトリの配置先も記録に残り続けるので、`--apply` は**全部まとめて**更新します
- **お知らせは1本にまとまります。** 「新版が出た」はリポジトリごとに変わらない情報なので、増やさず最新の1本に置き換えます

いま何件登録されているかは `--check` で見られます。

### 知らないうちに書き換わることはありません

**更新は自動では行われません。** メンターは読み取り専用なので自分を書き換えられませんし、知らないうちに挙動が変わるのも困るからです。**気づくのは自動、書き換えるのはあなた**、という形にしてあります。

**あなたが既に入れている別の hook 設定にも触りません。** 学習メンター以外の `SessionStart` 設定はそのまま残したうえで、メンターの分を足します。

## 🆘うまくいかないとき

| 症状 | 見るところ |
|---|---|
| メンターではなく普通のAIとして応答する | 起動方法が違います。定義ファイルを置くだけでは足りません → [learning-mentor-setup.md](learning-mentor-setup.md) |
| 「代わりに実装しましょうか？」と言ってくる | 同上。メンターではなく開発セッションが応答しています |
| いきなりレビューが返ってくる（説明を求められない） | 配置が効いていない可能性があります → [動作確認](#3-動作確認するここを飛ばさないでください) |
| `--check` が `hook     : ★ 一度も動いていません` を出す | お知らせが効いていません → [hooks/README.md](hooks/README.md) |
| `--apply` が「マーカーがありません」で飛ばす | 配置時にマーカー行が落ちています。配置し直してください |
