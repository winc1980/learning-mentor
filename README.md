# 学習メンター

**AIに「先生役」だけをやらせる設定です。** コードは書いてくれません。その代わり、解説・レビュー・トラブル対応をします。

> **注記：** まだ **1.0 に達していません。** 構成・手順・配置先の指定は今後変わることがあります。
> 新版が出たら `mentor-update.py --apply` で追従してください。
> いま配布されている版は [Releases](https://github.com/winc1980/learning-mentor/releases) が正です。

---

## これは何？

普通のAIは、頼めばコードを書いてくれます。便利ですが、**書いてもらったコードを自分で説明できないまま先に進むと、あとで壊れたときに直せなくなります。**

学習メンターは、そこをわざと逆にしてあります。

| | 普通のAI | 学習メンター |
|---|---|---|
| コードを書く | 書いてくれる | **書いてくれない** |
| 解説する | 頼めばする | **これが本業** |
| ゴール | 動くものが手に入る | **自分で書けるようになる** |

**急いで動くものが欲しいときは、こっちを使わないでください。** 普通のAIを使ってください。これは、理解を残したいときのための道具です。

### できること

| | 何をするか |
|---|---|
| **解説** | 分からない箇所を一緒に特定して、全体像から順に説明します。最後に「今の話、どう理解しました？」と聞かれます |
| **レビュー** | 先に「このコード、自分の言葉で説明できますか」と聞かれます。そのあと重大度つきで指摘します。**修正コードは書いてくれません** |
| **トラブル対応** | やりたいこと / 起きたこと / エラー全文 / 試したこと / **自分の仮説** の5つを揃えてから、原因を切り分けます |

トラブル対応で聞かれる5つは、**人に質問するときのテンプレとまったく同じ**です。AIに聞く練習が、そのまま人に聞くときの質問の質になります。

## 使い方

そのまま話しかけるだけです。

```
async/await って何ですか
このコード見てもらえますか
エラーが出て動きません
```

**途中で「これ何をしてると思いますか？」と聞かれます。** ここでうまく答えられなくて大丈夫です。「たぶん…データを取ってくる？」で十分ですし、「分からない」もちゃんとした答えです。テストではありません。

しんどければ「いまは説明したくない」と言えば、すぐ引きます。

> 詳しい使い方 → **[learning-mentor-quickstart.md](learning-mentor-quickstart.md)**（初めての人はこれを読んでください）

## 導入方法

Python 3 が必要です。`python` が使えない場合は `py -3` に読み替えてください。

### 1. ダウンロードする

[Releases](https://github.com/winc1980/learning-mentor/releases) から最新の `learning-mentor-vX.Y.Z.zip` を落として展開します。

### 2. 配置する

置き場所はツールによって違うので、**AI自身に調べさせて配置させます。**

展開したフォルダで、使っているAI（Claude Code、Codex CLI など）にこう頼んでください。

```
learning-mentor-setup.md を読んで、運用Bで配置してください
```

`運用B` のところに、下の表で選んだ **A** か **B** を書きます。

| | どんなとき | 何が起きるか |
|---|---|---|
| **A** | 学習用のリポジトリを作って、そこでは常にメンターに相談したい | そのリポジトリでは常にメンターとして応答します |
| **B** | 普段は普通に開発していて、必要なときだけ呼びたい | `learn` として登録され、呼んだときだけメンターになります |

あとはAIが環境を調べ、置き場所と**起動方法**を提案してくれます。承認すると、配置に続けて
`mentor-update.py --setup` まで実行します。ここで**置き場所の記録**と、**更新のお知らせ
（セッション開始時に新版を知らせる仕組み）の設置**が同時に済みます。あなたが設定ファイルを
手で編集する必要はありません。

> AIが手元のファイルを読めない環境（ブラウザ版など）では、[learning-mentor-setup.md](learning-mentor-setup.md) の枠を丸ごとコピーして貼る方法もあります。手順はそのファイルの冒頭にあります。

### 3. 動作確認する（★ここを飛ばさないでください）

**置き場所を間違えても、エラーは出ません。黙って無視されるだけです。** 「メンターを使っているつもりで、普通の開発セッションと話していた」が実際に起こります。

配置できたら、メンターを起動して**そのまま次の質問を貼ってください。**

```
使えるツールの名前を、箇条書きで全部挙げてください。
```

| 返ってきた一覧 | 判定 |
|---|---|
| 読み取り系だけ（`Read` `Grep` `Glob` など） | ✅ 成功 |
| `Edit` `Write` **やシェル実行**が入っている | ❌ 失敗。置き場所か起動方法が違います |

**「このファイルを書き換えて」と頼んで断られたかどうかでは判定できません。** ツールが無くてもAIは「〜という設定なので、できません」と自然に説明するだけなので、区別がつかないからです。**能力の有無は、ツール一覧にしか現れません。**

**Codex CLI だけは、この表では判定できません。** 読み取り専用に設定してもシェル実行がツール一覧に残るためです（2026-09-08 実機確認）。Codex を使う場合は、`learning-mentor-ops-guide.md` の「配置後の動作確認」にある Codex 用の手順に従ってください。

### 4. お知らせが効いているか確認する

手順2で更新のお知らせが自動設置されています。**効いているかは、セッションを1回起動したあとでないと分かりません。** 一度起動してから、`--setup` の最後に表示されたコマンドを実行してください。

```
python mentor-update.py --check
```

`hook : OK` と出れば効いています。`★ 一度も動いていません` なら効いていません → [hooks/README.md](hooks/README.md)

**既に別の `SessionStart` 設定がある場合、`--setup` は何も書き込みません。** 既存の設定を壊さないためです。代わりに「この内容を手で足してください」と表示されるので、その手順に従ってください。

## 更新方法

```
python mentor-update.py --apply
```

これだけです。最新版かどうかの確認も中で行うので、事前に調べる必要はありません。すでに最新なら「すでに最新です」と表示して終わります。

新版があれば、何がどう変わるかを表示してから `y / N` を聞かれます。更新前のファイルは `.bak` で残るので、戻せます。

> 配置先の状態・お知らせが効いているか・最新版の有無をまとめて見たいときは `--check` です。更新はしません。

**更新は自動では行われません。** メンターは読み取り専用なので自分を書き換えられませんし、知らないうちに挙動が変わるのも困るからです。**気づくのは自動、書き換えるのはあなた**、という形にしてあります。

### 更新したら、もう一度動作確認を

更新は本文を丸ごと入れ替えます。上の **3. 動作確認**（ツール一覧の確認）を、更新のたびに通してください。`--apply` の最後に同じ手順が表示されるので、それに従えば十分です。

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| メンターではなく普通のAIとして応答する | 起動方法が違います。定義ファイルを置くだけでは足りません → [learning-mentor-setup.md](learning-mentor-setup.md) |
| 「代わりに実装しましょうか？」と言ってくる | 同上。メンターではなく開発セッションが応答しています |
| いきなりレビューが返ってくる（説明を求められない） | 配置が効いていない可能性があります → 上の動作確認 |
| `--check` で「hook が一度も動いていません」 | お知らせ機能が効いていません → [hooks/README.md](hooks/README.md) |
| `--apply` が「マーカーがありません」で飛ばす | 配置時にマーカー行が落ちています。配置し直してください |
