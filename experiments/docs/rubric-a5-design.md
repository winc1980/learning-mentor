# rubric-a5.md の設計意図（採点者には見せない内部ドキュメント）

`experiments/rubric-a5.md` は採点者サブエージェントにそのまま渡すファイルなので、
**なぜこの形にしたか」はそちらに書けない。書くと採点者に仮説がばれる。** ここに退避する。

## 何のための第二ルーブリックか

A-5（issue #6）は現行プロンプトと wex-fine の**横並び比較**。`rubric.md` の
「完成コード相当」は現行メンターの規約（コードを書かない）を守っているかを判定する項目で、
**単一の規約を前提にした合否判定**になっている。wex-fine は規約そのものが逆
（1ブロックだけ完成コードを見せるのが仕様）なので、同じ項目をそのまま使うと
「wex-fine が仕様通り動くほど違反として採点される」という極性の反転が起きる。

## 合否を判定しない設計にした理由

`rubric-a5.md` は条件（現行 or wex-fine）ごとに合否が逆転する項目を含むため、
採点者に条件を明かさずに合否を聞くことができない。そこで**合否の判定自体を
やめ、観測事実だけを客観的に数える**設計にした。「それが良いか悪いか」は
条件が分かっている集計フェーズ（analyze.py 側、未実装）で解釈する。

主指標は「提示ブロック数」。ただし単純な出現数ではなく、
**開発者のプロジェクト固有の識別子を使ったブロックだけを数える**という定義にした。
これが無いと、現行メンターに許されている汎用例示コード（10行以内・一般名）まで
数えてしまい、両条件の対称性が崩れる（現行=0 / wex-fine=1 という対称な期待値が壊れる）。

②③（ブロック後の問いの段、圧力追従）は issue #6 のコメントで補助指標に降格済み。
主指標が崩れていないセルでのみ参照する方針（この優先順位づけ自体は analyze.py 側の役割で、
ルーブリック本文には書かない）。

## rubric.md との関係、あえて分離・複製した理由

- `rubric.md`（版2）は今後も現行プロンプト単独実験（001〜006系）に使い続ける。
  差し替えではなく別ファイル。
- `rubric-a5.md` は `rubric.md` への参照を一切含まない。**採点者サブエージェントが
  「最初の問い」の定義を確認しようとして `rubric.md` を読みに行くと、そこに
  現行メンターの規約（コードを書かない、等）が書かれており、間接的に比較対象の
  存在がばれる。** そのため「ブロック後の問いの段」のL1〜L4定義とモード分類は
  `rubric-a5.md` 内に**そのまま複製**した。
- **複製の副作用：定義が2箇所にある。** `rubric.md` のはしご定義（L1〜L4）が
  将来版3で変わった場合、`rubric-a5.md` 側は自動追随しない。変更する際は
  両ファイルを手動で同期すること。

## タイトルから「比較」を外した理由

`rubric-a5.md` は採点者に直接渡るため、ファイル名・見出し・本文のどこにも
「比較」「現行 vs wex-fine」を書かない。タイトルは「採点ルーブリック（盲検）── wex-fine評価用」
に留め、wex-fine の応答を評価しているとしか分からないようにする。
