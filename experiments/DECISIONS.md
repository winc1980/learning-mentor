# 測らないと決めたこと

**ここに書いてあるものは issue にしない。** issue は閉じると忘れられるが、これは
**将来の提案を却下するための根拠**なので、閉じてはいけない。

新しく測りたいものを思いついたら、まずここを読むこと。一度否定された設計が、
半年後に別の名前で戻ってくるのを防ぐためのファイル。

---

## コンテキスト量を独立変数として扱うこと

**004 で否定された。** Claude Code のバックグラウンド先読みにより、**質問の粒度が
コンテキスト量を決めてしまう。** そもそも独立に操作できない。

量は結果として記録するに留める。「コンテキストが増えると崩れる」という当初の仮説は、
実際には「直前のターンで詳細解説を済ませていると崩れる」だった。

---

## `問い返し密度` を指標として使うこと

字数と交絡し、日本語の疑問形も取りこぼす。**参考値以上には使わない。**

`質問文数` も同様（体言止めの問いや選択肢提示を拾えていない）。二値の「理解確認が先行」は
採点者の判断に任せる方針なので、精度を上げる価値が薄い。

---

## 人格残存度の5段階を主指標にすること

**二値の「理解確認が先行」のほうが安定している。** 5段階は補助に降格する。

理由。「地図を渡してから確認する」形が段5か段4かが未定義で、006 では一致 20/20 だったのに
003 の再採点では 3/10 まで落ちた。**条件依存で不安定。** 一方、結論はすべて二値に依拠しており、
そちらは全 run で一致が高い。段5と段4はどちらも健全側なので、区別する必要がそもそもない。

**やるとしたら：** 段5を「地図も含めて、解説的な出力より前に確認がある」と定義し直し、
既存の判定済みデータを再採点して一致率を測る（新規セル不要、約 $2）。
**人格残存度を対外的な指標として使う予定が立つまで、やらない。**

---

## タスク粒度（当初計画の C-4）を単独で測ること

粗 / 中 / 細の3水準を単独で回す計画だったが、**粒度の効果は 002〜006 で実質的に測り終えている。**
probe_grain（fine / coarse）が全 run で要因に入っており、004 で「質問の広さ」が
2経路の片方そのものだと分かった時点で、独立に測る意味が薄れた。

---

## 参加者の選好を判定に使うこと

学習会で「正解のコードを見せてほしい」という声が出た（#6 の起点）。
**これは学習者が何を期待するかの表明であって、どちらが学習に効くかの証拠ではない。**

**選好と学習効果は乖離することが知られている。** 固定台本で測れるのは規定の遵守だけで、
学習効果の外的妥当性は #4（実学習者の観察）に依存する。

観察するときも**選好は聞かない。** 聞くと選好で決めたくなる。見るのは
「どちらで手が止まったか」「どちらの説明が返ってきたか」。
