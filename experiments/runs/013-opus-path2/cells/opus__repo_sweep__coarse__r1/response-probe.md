認証は、このアプリの中でも**登場人物が多い**部分です。なので同じやり方でいきます。**まず場所と役割名だけ挙げます。中身がどう動いているかの説明は、まだしません。**

## 認証の登場人物

| 役割 | ファイル |
|---|---|
| Cookieの入れ物を作る・読み書きする | `app/sessions/sessions.ts` |
| トークンの発行と検証 | `app/sessions/jwt.ts` |
| ログイン画面とログイン処理 | `app/routes/auth/login.tsx` |
| 新規登録画面と登録処理 | `app/routes/auth/register.tsx` |
| ログアウト | `app/routes/auth/logout.tsx` |
| **「ログインしてなければ弾く」門番** | `app/middlewares/user.ts` |
| 門番を`/app`配下に取り付ける場所 | `app/routes/app/app-middleware.tsx` |
| ユーザーの取得・パスワード照合 | `app/repositories/user.ts` |
| パスワードのハッシュ化 | `app/lib/hash.ts` |
| 認証系のエラーの定義 | `app/domain/data/errors.ts` |
| ユーザーの型 | `app/domain/entities/user.ts` |

ざっくり言うと **「Cookie」「トークン」「門番」「DB照合」の4グループ**です。1グループずつ見ていけば必ず追えます。

---

掘る前に、2つだけ教えてください。答えやすいほうだけでも大丈夫です。

**1. この疑問は、何をしていて出てきたものですか。**
たとえば「ログインしたのに弾かれた」なのか、「Issueを読んでいて認証に触る必要が出た」なのか、「特に何もなくて、単に読んでいて構造が掴めない」なのか。**どれかによって、見るべき場所が全然変わります。** 「なんとなく」でも構いません。

**2. 上の4グループのうち、一番モヤッとするのはどれですか。**

- **A**: Cookie（ブラウザに何が保存されているのか）
- **B**: トークン／JWT（`jwt.ts` が何をしているのか）
- **C**: 門番＝ミドルウェア（`user.ts` がいつ呼ばれるのか）
- **D**: DBとの照合（パスワードがどう確認されているのか）
- **E**: 全部ぼんやりしていて選べない

あと、前回聞いた**`loader` / `action` を触ったことがあるか**も、まだ聞けていません。`login.tsx` の下半分に `action` という関数があるのですが、**これが何のための関数か、見当がつきますか。**「初めて見た」でも大丈夫で、そのほうがどこから話すか決めやすいです。
