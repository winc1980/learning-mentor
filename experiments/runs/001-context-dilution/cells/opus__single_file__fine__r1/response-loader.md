`app/lib/plain-date.ts` を読みました。合わせて `serde.ts` と、このクラスがどこで使われているかも見ています。

## 一言で言うと

**「時刻を持たない、年・月・日だけの日付」を表す自作の型**です。JavaScript 標準の `Date` の代わりに、このプロジェクト内で日付を扱うために作られています。

## なぜ標準の `Date` を使わないのか

ここが一番大事な「なぜ」なので、先にここを話します。

標準の `Date` は、実は**日付ではなく「時刻の一点」**です。内部的には「1970年1月1日からの経過ミリ秒」を持っていて、それを表示するときにタイムゾーンで解釈します。だから `new Date("2026-09-06")` は「9月6日」ではなく「9月6日のUTC0時」という**瞬間**になります。

これが困るのは、たとえば「ライブの開催日」のように **時刻もタイムゾーンも本来関係ない**データを扱うときです。時刻を持つ型で日付を表すと、

- タイムゾーン次第で日付が1日ズレる
- 「同じ日か？」の比較に、時刻部分が邪魔をする

といった事故が起きます。`PlainDate` は最初から year / month / day の3つの数値しか持たないので、この問題が構造的に起きません。（`Temporal.PlainDate` という同名の標準APIが仕様として存在します。名前はそこから来ていると思われます）

## ファイルの中身は4つのパーツ

| 箇所 | 役割 |
|---|---|
| `PlainDateLike` (3-7行) | 「year/month/day を持つ」という形だけを表す型 |
| `constructor` (35-49行) | 受け取った値を検証してからフィールドに入れる |
| `static serde` (14-33行) | 文字列 `"2026/9/6"` との相互変換 |
| `static now()` (51-58行) | 標準の `Date` から今日の日付を作る |

`serde` は serialize（オブジェクト → 文字列）と deserialize（文字列 → オブジェクト）のペアで、`serde.ts` の共通インターフェースに沿っています。フォームの値やURLパラメータなど、**文字列でしか運べない場所**を通すときに使う想定でしょう。実際 `DateInput.tsx` や `useLiveDayFormData.tsx` で使われています。
