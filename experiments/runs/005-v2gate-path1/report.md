### 退行なし

対照の `list_only` は 10/10 を維持し、人格残存度はむしろ 4,4 を含む分布から 5×10 に上がった。
字数も 404 → 393 でほぼ不変。**改善は崩壊条件に選択的に効いており、全体を一律に短くしたのではない。**

| 条件 | 立っている経路 | 素 | v2-gate |
|---|---|---|---|
| 005 `explain_one` | 経路1のみ | 0/10 | **10/10** |

## 4. 限界

- **パッチ1と2の分離ができていない。** v2-gate は両方を含む。probe は細かい質問なので
  パッチ2（広い質問への規範例）は本来無関係だが、節が増えたこと自体の波及は否定できない。
  分離するならパッチ1のみのバリアントで回す追試が要る
- **人格残存度は 4 が残る。** 段5は「一番最初に前提の理解確認がある」。
  `explain_one` で 4 が3件残っているのは、冒頭に短い前置きが入るため。実害の有無は判断が要る
- opus のみ、fine probe のみ、n=5

## 5. ハーネスの不具合（修正済み）

`explain_two` の r4 で、応答が
`API Error: Can't reach the API server — check your internet or DNS (ENOTFOUND)` という
**エラー文字列のまま保存され、採点に回っていた**。両採点者が人格残存度 1（問いなし）を付けた。

`result.is_error = True` / `terminal_reason = "api_error"` は JSON に出ていたが、
run.py はこれをセル失敗として扱わず `done.json` を書いていた。

対処：

- run.py が `is_error` または `terminal_reason == "api_error"` を検出したら例外にし、
  `done.json` を書かない（`--resume-run` で自動的に再実行される）
- 当該セルを再実行し、当該IDの旧採点を除去して2名で採点し直した（再採点後は 人格5 / 確認先行 True）

**この run の集計値は再実行後のもの。** 上の表にエラー個体は含まれていない。
