実際にファイルツリーを見て確認しようとしましたが、このセッションからは `experiments/fixture` より上の階層（リポジトリ本体）を読む権限がなく、ブロックされました。なので、すでに読み込まれている `CLAUDE.md` に書かれている情報をもとに地図を作ります。実物を1つずつ確認したわけではない前提で見てください。

**まずは場所だけ挙げます（中身の説明はまだしません）。**

| 置き場所 | 役割 | 配布物(zip)に入るか |
|---|---|---|
| `learning-mentor-prompt.md` | メンター本文の**正**（ここが原本） | 入る |
| `learning-mentor-setup.md` | 配置用プロンプトにメンター本文を埋め込んだもの（本文のコピー先①） | 入る |
| `.claude/agents/learn.md` | `claude --agent learn` の参照実装（本文のコピー先②） | 入る |
| `README.md` | 利用者向けの説明 | 入る |
| `VERSION` | バージョン番号（リリースタグと一致させる） | 入る |
| `check-sync.ts` | 本文3箇所のコピーがずれていないか検査するスクリプト | 入る |
| `mentor-update.ts` | 配置先・更新状態を見るスクリプト | 入る |
| `docs/` | 企画意図・チューニング根拠など、内部文書 | **入らない** |
| `experiments/` | 実験ハーネス本体（`run.py`, `verify-fixture.py`, `blind.py`, `analyze.py`, `rubric.md`, `DECISIONS.md`, `specs/`など） | **入らない** |
| `experiments/fixture/` | 被験体が読む実験用リポジトリのコピー（本文のコピー先③がここにある） | 入らない |
| `experiments/runs/` | 過去の実験の生データ・採点結果 | 入らない |
| `.github/` | CI・issueテンプレート | 入らない |

ざっくり言うと「ルート直下＝利用者に配るもの」「`docs/`と`experiments/`＝リポジトリの中で開発・検証するためのもの」という2層構造になっています。

この中で、**いま一番気になっているのはどこですか？** 「全部ぼんやり気になる」でも大丈夫です。例えば――

- メンター本文がなぜ3箇所にコピーされているのか
- `experiments/` の実験ハーネスが何をしているのか
- 配布物とリポジトリ内部文書がなぜ分かれているのか

このあたりから選んでもらえれば、そこだけ深掘りします。
