## 2. 経路1を落とした理由

011 で、sonnet は `single_file` loader に詳細解説を返さないことが分かっている
（混入あり 184 字 / 混入なし 188 字）。経路1は「直前のターンで詳細解説を済ませている」
状態を前提にするので、**sonnet ではその状態に入らない。** 回しても操作が効かないことの
確認にしかならないため、測っていない。

**これは「sonnet が経路1に強い」という意味ではない。** 004 の設計では測れない、という意味。

## 3. この run 単独では 002 と比較できない

当初この run は 002（opus / B・D・F）との比較を想定していた。**成立しない。**

`a398e78`（2026-09-07 16:33）で **v2-gate のパッチが配布本文そのものに取り込まれている**
（`learning-mentor-prompt.md` の 160 行目・178 行目）。さらに `35d7e59`（09-08）が
L3/L4 の入れ替えと分量上限の撤廃を入れている。

| run | 実行日 | 本文 |
|---|---|---|
| 002（opus） | 2026-09-06 | v2-gate **前** |
| 004（opus） | 2026-09-07 10:04 JST | v2-gate **前** |
| 012（sonnet） | 2026-09-11 | **現行**（v2-gate + 09-08 の変更） |

**012 対 002 はモデルとプロンプトの両方が違う。** D が 0/10 → 10/10 になったのが
sonnet のおかげか v2-gate のおかげか、この2つでは分離できない。

### どう見えなかったか

`check-sync.ts` は本文と3箇所のコピーが一致していることを保証する。`run.py` は毎回それを
通す。だから**どの run も「本文と同期した learn.md」で走っており、検査は全部通る。**
検査していないのは「**その本文が、比較先の run の本文と同じか**」である。
manifest には spec と fixture SHA は残るが、**配布本文のバージョンは残っていない。**

この対照として 013（opus / 現行本文 / 同一条件）を回した。差は `model` の1行だけ。
