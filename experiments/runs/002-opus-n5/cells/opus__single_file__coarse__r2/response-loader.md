`app/lib/plain-date.ts` を読みました。全体像から話しますね。

## 一言で言うと

**「時刻を持たない、日付だけの値」を表すための自作の型**です。2026年9月7日、という情報だけを持ち、「何時何分か」「どのタイムゾーンか」は一切持ちません。

## なぜこれが必要なのか

JavaScript 標準の `Date` は、名前に反して**日付ではなく「ある瞬間」**を表します。内部的には「1970年からの経過ミリ秒」であって、必ず時刻とタイムゾーンがくっついてきます。

これが「ライブの開催日」のようなものを扱うときに困ります。よくある事故が、

- `new Date("2026-09-07")` が UTC の 0時 と解釈される
- それを日本時間で表示すると **9月7日 9:00**
- 逆方向にずれる条件だと **9月6日** になってしまう

日付しか要らないのに、時刻とタイムゾーンという「余計な情報」が付いてくるせいで、1日ずれるバグが生まれる。だったら最初から `year` `month` `day` の3つの数字だけ持つ型を自分で作ってしまおう、というのがこのファイルの動機です。

（余談ですが、JS にこの不満を解消する `Temporal.PlainDate` という新標準が来ていて、この `PlainDate` という名前はそこから取られている可能性が高いです）

## 中身は3つのパートだけ

1. **コンストラクタ（35〜49行）** — 3つの数値を受け取る。ただし受け取る前に、月が1〜12か、日が1〜31かをチェックして、範囲外なら例外を投げる。「不正な値を持った `PlainDate` はそもそも存在できない」状態を作っています

2. **`serde`（14〜33行）** — `"2026/9/7"` のような**文字列との相互変換**。`serialize` が値→文字列、`deserialize` が文字列→値です。フォームの入力値や URL、DBに保存するときは文字列にせざるを得ないので、その出入口をここに閉じ込めています

3. **`now()`（51〜58行）** — 標準の `Date` から今日の日付を取り出して `PlainDate` にする。`getMonth()` が 0始まり（1月が0）なので `+ 1` している、あの有名な罠への対応がここに入っています
