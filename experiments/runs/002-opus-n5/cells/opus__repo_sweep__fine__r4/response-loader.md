## 1. これは何のアプリか

**軽音サークルのライブ・タイムテーブル管理アプリ**です。ドメイン（扱っている対象）を並べるとこうなります。

- `user` … ユーザー
- `live` / `live-day` … ライブと、その開催日
- `band` / `band-participation` … バンドと、誰がどのバンドにいるか
- `live-application` … バンドからライブへの出演申し込み
- `band-availability` … バンドがどの日時に出られるか

つまり「ライブを作る → バンドが申し込む → 各バンドの空き時間を集める → タイムテーブルを組む」という流れのアプリです。

そしてREADMEにある通り、**意図的に壊れている／未実装の箇所があります**（Issue 1〜7）。なので「このコードは全部お手本」という前提では読まないほうがいいです。

## 2. 技術スタック

`package.json` から読み取れる主役は3つです。

| | 何をするもの |
|---|---|
| **React Router v8**（フレームワークモード） | ルーティングだけでなく、サーバー側の処理も担当する。Next.jsの対抗にあたるフルスタックフレームワーク |
| **Drizzle ORM** + **libSQL** | DBアクセス。SQLをTypeScriptで型付きで書けるようにするライブラリ + SQLite系のDB |
| **Tailwind CSS** + **shadcn/ui** + **Radix UI** | 見た目。shadcn/uiは「ライブラリをインストールする」のではなく、コンポーネントのコードが自分のリポジトリにコピーされる方式 |

ほかに `valibot`（入力値の検証）、`jose`（JWT＝ログイン状態を保持するトークンの生成・検証）、`bcrypt`（パスワードのハッシュ化）。

## 3. ディレクトリの地図

```
app/
  routes.ts        ← URLとファイルの対応表。ここが入口
  routes/          ← 各ページ（と一部API）
  root.tsx         ← アプリ全体の外枠HTML

  db/              ← DB接続とテーブル定義
  repositories/    ← DBへの読み書きをまとめた場所
  middlewares/     ← 各ページの手前で走る共通処理
  domain/          ← アプリ固有の「型」と「ルール」
  components/      ← UI部品（common = 自作 / ui = shadcn由来）
  hooks/           ← Reactの自作フック
  lib/             ← 汎用ユーティリティ（日付、ハッシュ、Result型など）

drizzle/           ← DBスキーマの変更履歴（マイグレーション）
docs/              ← 環境構築・進め方
issues/            ← 課題7本の説明文（setup時にGitHubへ登録される）
```

## 4. 一番大事なところ：リクエストが流れる道

ここがこのリポジトリの背骨です。`app/routes.ts` を見ると、URLがきれいに入れ子になっています。

```
/                      root-layout
/auth/login            ログイン系
/app                   app-middleware → app-layout → ページ
/app/live/:liveId      ↑ に live-middleware → live-layout → ページ
/app/live/:liveId/band/:bandId   さらに band-middleware → band-layout
```

`layout(...)` で囲まれた中のURLは、**必ず外側のファイルを通ってから**中のページに届きます。だからこのアプリでは、

- `*-middleware.tsx` = 「ログインしてる？そのライブ見る権限ある？」のチェック役（通さない場合はここでリダイレクト）
- `*-layout.tsx` = 共通の見た目（ヘッダーやタブ）
- ページ本体 = 中身だけに集中できる

という役割分担になっています。`app/middlewares/` の4ファイルは、この中で使われる実処理です。

そして各ページの中は、React Routerの規約で**だいたい3つの部分**に分かれています。ページファイルを開くと同じ形が繰り返し出てくるはずです。

- サーバーで「表示に必要なデータを取ってくる」部分
- サーバーで「フォーム送信を受け取って書き込む」部分
- ブラウザで「それを描画する」部分

データの流れを一直線にするとこうです：

```
ページ → repositories/ → db/ → SQLite
              ↑
        domain/ と lib/ が型とルールを提供
```
