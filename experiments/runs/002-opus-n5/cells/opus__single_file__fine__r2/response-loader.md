`app/lib/plain-date.ts` を読みました。まず全体像だけ先に話して、そのあと細かいところに入りましょう。

## 一言で言うと

**「年・月・日だけを持つ日付」を表す自前の型**です。時刻（何時何分）もタイムゾーンも持ちません。

## 何のためにあるのか

JavaScript 標準の `Date` は、名前に反して「日付」ではなく **世界のどこかの一瞬（時刻）** を表しています。なので「2026年9月7日」というカレンダー上の1日を扱いたいだけなのに、標準の `Date` を使うと

- 必ず時刻（00:00:00 など）がくっついてくる
- その時刻はタイムゾーン次第で「前日」や「翌日」に化ける

という余計な問題を背負い込みます。ライブの開催日や応募可能日みたいな「カレンダー上の日付」には、時刻もタイムゾーンも本来いらない。**いらないものを持たない型を自分で作った**、というのがこのファイルの動機です。

（`PlainDate` という名前は、JavaScript に入る予定の新しい日付API「Temporal」の `Temporal.PlainDate` から来ています。"Plain" = タイムゾーンが付いていない、という意味です）

実際、このプロジェクトでは `app/domain/entities/live-day.ts` や `live-application.ts` など11ファイルで使われていて、日付を扱う共通の土台になっています。

## 中に入っているもの（4つだけ）

| 場所 | 役割 |
|---|---|
| `PlainDateLike` 型 | 「year/month/day を持つ」という形だけの定義 |
| `constructor` | 生成時に月1〜12・日1〜31をチェックして、変な値のインスタンスを作らせない |
| `static serde` | 文字列 `"2026/9/7"` ⇄ `PlainDate` の相互変換 |
| `static now()` | 今日の日付を作る |
