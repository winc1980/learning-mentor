## まず、これは何のリポジトリか

**軽音サークルのライブ用タイムテーブル作成アプリ**です。ただし、普通のプロダクトのリポジトリではなく、**学習会（Phase 2）用の教材**として作られています。

READMEにこう書いてあります：

> - 所々、壊れて動かない箇所がある
> - Issueを解決しながら技術の実装を学ぶ

つまり **わざと壊してある／わざと雑に書いてある箇所がある**前提のコードです。「なんでこんな書き方なんだ？」と思う箇所に出会ったら、それが課題かもしれない、という目で見ると混乱しにくいです。

課題は `issues/` に7本入っています（環境変数、useEffect、リンター導入、コンポーネント分割、loader化、バリデーション など）。

## `app/` の中身 ── ここが本題

`app/` は**役割ごとにディレクトリが切られています**。下の層ほどDBに近い、と思ってください。

```
routes/        ← 画面とURL（一番外側）
  ↓
middlewares/   ← 認証・共通の前処理
  ↓
repositories/  ← DBへの読み書きの実装
  ↓
db/            ← テーブル定義・接続
```

これとは別に、横断的に使うものが3つ：

- `domain/` — アプリが扱う概念の型定義（`Band`, `Live`, `User` など）。中身は本当に型だけです
- `components/` — 画面部品。`ui/`（shadcn/uiが生成した汎用部品）と `common/`（このアプリ独自の部品）に分かれています
- `lib/` `hooks/` `sessions/` — ユーティリティ、独自フック、JWT/セッション処理

### `routes/` の構造

URLの形は `app/routes.ts` が定義しています。ファイルの場所ではなく**この1ファイルがURLの正解**なので、迷ったらここを見てください。

大きく3ブロック：

- `routes/home.tsx` — トップページ（未ログインでも見える）
- `routes/auth/` — login / logout / register
- `routes/app/` — ログイン後の本体。さらに `live/:liveId/` の下に、ライブ詳細・出演申込・タイムテーブル・バンドごとの空き時間入力…とネストしています

ネストの中に `*-middleware.tsx` と `*-layout.tsx` が交互に出てきます。ここがこのアプリの設計の要なので、あとで掘るならここが一番おいしいです。

### データの流れ（例：バンドの空き時間ページ）

```
URL /app/live/1/band/2/availability
  → app-middleware（ログイン確認・repositoryを用意）
  → live-middleware（liveId=1 を取得）
  → band-middleware（bandId=2 を取得）
  → availability.tsx が画面を描く
```

`middlewares/repositories.ts` を見ると、リポジトリを毎回 `new` して `context` に詰めています。各ページはDBを直接触らず、この context 経由で受け取る形です。

## DBのテーブル（`app/db/schema.ts`）

7テーブルです。関係を言葉にすると：

- **user** がいて、**live**（ライブ）を作る
- **band** にはリーダー（user）がいる
- **band_participation** が「どのbandがどのliveに出るか」を繋ぐ（承認フラグ付き）
- **live_day** が「ライブの開催日と時間帯」
- **band_availability** が「そのbandがその日いつなら出られるか」
- **live_application** はトークン付きの外部向け出演申込

つまり **「各バンドの空き時間を集めて、タイムテーブルを組む」** のがこのアプリの中心機能です。
