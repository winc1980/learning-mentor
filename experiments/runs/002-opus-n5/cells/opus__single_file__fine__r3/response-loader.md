## 一言でいうと

**「2026年9月7日」のような “カレンダー上の日付だけ” を表す、自前の型**です。時刻もタイムゾーンも持ちません。

このリポジトリでは、ライブの開催日や応募日など「日付」を扱うところで広く使われています（`live-day.ts`、`DateInput.tsx`、`availability.tsx` など11ファイル）。

## 中身は3つの部品

| 部品 | 役割 |
|---|---|
| `constructor` | year/month/day を受け取る。**月が1〜12、日が1〜31の範囲外なら例外を投げる** |
| `static serde` | `PlainDate` ⇄ `"2026/9/7"` という文字列の相互変換。`serialize` で文字列化、`deserialize` で文字列から復元 |
| `static now()` | 今日の日付を `PlainDate` として作る |

`serde` の型は `serde.ts` にある `Serde<Self, Serialized>` インターフェースで、「シリアライズ／デシリアライズのペアを持つもの」という共通の形を決めています。フォームの値やURLパラメータなど、**どうしても文字列にせざるを得ない場所**との境界で使うためのものです。

## なぜ自前の型を作るのか

ここが一番の「なぜ」なので、いきなり答えを言わずに一つ聞かせてください。

JavaScript には標準の `Date` があります。それでも開発者がこの `PlainDate` をわざわざ作った理由が何かあるはずです。

**正確じゃなくて大丈夫です。単語だけでも、「たぶん〜」でも構いません。** 言葉にすると自分でどこが曖昧か見つかるので、その材料として聞いています。

次のどれに近いと思いますか。「分からない」でも構いません。

- **A**: 標準の `Date` は時刻やタイムゾーンも持っていて、日付だけ扱いたいときに邪魔になるから
- **B**: 標準の `Date` は書き方が面倒だから、短く書けるようにしたかった
- **C**: 標準の `Date` だと文字列に変換できないから

（もし「そもそも標準の `Date` をあまり触ったことがない」ということであれば、そう言ってください。そこから説明します。）
