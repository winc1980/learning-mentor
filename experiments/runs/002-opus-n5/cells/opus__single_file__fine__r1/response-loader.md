`app/lib/plain-date.ts` を読みました。一言でいうと、**「年・月・日だけを持つ日付」を表す自作の型**です。

## なぜこれが必要なのか（一番大事なところ）

JavaScript 標準の `Date` は、**必ず時刻とタイムゾーンを持ちます**。`new Date()` は「2026年9月7日」ではなく「2026-09-07T14:32:10 JST」のような一点の瞬間を表します。

これが「ライブの開催日」のような値と相性が悪い。開催日に時刻は要らないのに、`Date` を使うと必ず時刻がくっついてきて、

- 「9/7 00:00 JST」は UTC では「9/6 15:00」なので、扱う場所によって**日付が1日ずれる**
- 意味のない時刻部分が混ざるせいで、**同じ日どうしの等値比較が成り立たない**

こうした事故が起きます。なので「時刻を持たない日付」という別物の型を用意している。ちなみに `PlainDate` という名前は、JS に入りつつある新標準 `Temporal.PlainDate` から借りたもので、「plain = タイムゾーンや時刻が付いていない素の」という意味です。

## ファイルの中身は4パート

**1. `PlainDateLike`（3〜7行目）**
`{ year, month, day }` という形さえ持っていれば何でも当てはまる型。クラスのインスタンスでなくても受け取れる、という受け口です。

**2. `constructor`（35〜49行目）**
月が1〜12、日が1〜31の範囲かを確認して、外れていれば例外を投げます。狙いは、**不正な値を持った `PlainDate` がそもそも生成できない状態を作る**こと。生成時に一度弾いておけば、以降このオブジェクトを受け取る側は「値は妥当」と前提してよくなります。

**3. `static serde`（14〜33行目）**
`"2026/9/7"` という文字列との相互変換です。オブジェクトを文字列などに変換することを**シリアライズ**、その逆を**デシリアライズ**と呼びます。`serde.ts` の `Serde<Self, Serialized>` インターフェースを実装する形になっていて、「この型の変換ルールはここにある」と型で示しています。

**4. `static now()`（51〜58行目）**
今日の日付を作ります。`getMonth()` は0始まり（1月が0）なので `+ 1` しています。
