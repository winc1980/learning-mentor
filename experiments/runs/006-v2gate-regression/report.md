## 2. 測定上の重大な問題と、その解決

### 起きたこと

最初の採点で **採点者間一致が崩れた**（人格残存度 11/20、理解確認が先行 11/20）。
不一致は条件で完全に分離していた。

| 条件 | 確認先行の一致 |
|---|---|
| A（fine） | 5/5 |
| **B（coarse）** | **0/5** |
| E（fine） | 5/5 |
| **F（coarse）** | **1/5** |

根拠欄に理由が明示されていた。同一の応答に対して：

> judge-M「**場所一覧のみ**提示後に関心箇所と経験を確認」→ 確認先行 **true**
> judge-N「役割一覧が**先**。経験の確認は**説明の後**に配置」→ 確認先行 **false**

**ルーブリックが「地図を渡すことは解説にあたるか」を定義していなかった。**
v2-gate が新設した「場所だけ先に示す」パターンが、この未定義領域を踏んだ。

### 解決

「**地図は解説ではない**」と裁定し、rubric.md に判定表つきで明記した。
境目は中身を説明したかどうか。宣言文ではなく実際の中身で判定する
（「中身の説明はまだしません」と書いてあっても実際に説明していれば false）。

再採点の結果、**全項目 20/20 の完全一致**になった。上の表は再採点後の値。

旧採点は `blind/judgments-raw-v1-mapundef/` に保存してある。

### この裁定のバイアスについて

この裁定は v2-gate のパッチ2を正当化する向きに働く。基準が片側だけに有利に効いていないかを確認した：

- 002 の B（**素のプロンプト**・地図パターン）は、旧採点でも一致して 10/10 だった。
  素のプロンプト側も同じ基準で評価されている
- 002 の D・F は地図ではなく本格的な解説だったため、裁定の影響を受けず 0/10 のまま

**基準は両側に同じように適用されている。**

## 3. 訂正 — 003 と 005 の記述

同じ曖昧さは 003（全条件 coarse）にも及んでいた。003 も再採点した結果：

| | 旧ルーブリック | 新ルーブリック |
|---|---|---|
| 003 D | 6/10 | **10/10** |
| 003 F | 8/10 | **10/10** |

したがって次の2つの記述は誤りであり、撤回する。

1. **003**「経路2の戻りは 8/10 に留まる」「D は 6/10」
2. **005**「戻りの悪い順が、立っている経路の数と一致している」

**v2-gate は経路1・経路2・両方立つ条件のいずれでも 10/10 に戻している。**
経路ごとに戻り方が違うという所見は、測定器の未定義部分が生んだ数値だった。

この誤りは、004 の2経路モデルと符合していたために説得力があるように見えた。
**仮説によく合う結果ほど、測定器を先に疑うべきだった。**

## 4. 残る測定上の限界

人格残存度の 4 と 5 の境目には、同じ曖昧さが残っている。
段5は「**一番最初に**前提の理解確認があるか」だが、地図を挟んだ場合に「最初」と見なすかが未定義。

003 の再採点では人格残存度の一致が 3/10 まで落ちた（理解確認が先行は 10/10）。
006 では 20/20 だったので条件依存だが、**このスケールを今後も使うなら段5に但し書きが要る。**

ただし**現時点の結論は影響を受けない。** 割れているのは 4 と 5 の間だけで、
どちらも「確認が解説より前にある」健全な側であり、結論は理解確認が先行に依拠している。
