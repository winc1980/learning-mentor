認証は5つの登場人物に分かれています。**ここでも、まずは場所だけ挙げます。中身がどう動くかの説明はまだしません。**

---

## 認証の登場人物

| 役割 | ファイル |
|---|---|
| Cookie の入れ物を作る・読む・書き戻す | `app/sessions/sessions.ts` |
| トークンの発行と検証 | `app/sessions/jwt.ts` |
| パスワードのハッシュ化と照合 | `app/lib/hash.ts` |
| ページ表示前の「門番」 | `app/middlewares/user.ts` |
| 入口の3ページ | `app/routes/auth/login.tsx` / `register.tsx` / `logout.tsx` |

## 門番がどこに刺さっているか

これは `app/routes.ts` と `app/routes/app/app-middleware.tsx` の2ファイルで決まっています。

- `app/routes/app/app-middleware.tsx` … 5行しかないファイルです。門番を1個くくり付けているだけ
- `app/routes.ts` の 18行目 … そのファイルが `/app` 以下全部を包む位置に置かれています

つまり「どのURLが要ログインか」は、この2箇所を見れば分かる、という構造です。

## ついでに関わってくるもの

| | |
|---|---|
| ユーザーのDB読み書き | `app/repositories/user.ts` |
| `UserNotFoundError` などのエラー種別 | `app/domain/data/errors.ts` |
| 成功／失敗を包む型（認証コードが全面的に使っている） | `app/lib/result.ts` |

地図はここまでです。ここから2つ聞かせてください。

**1. この中で、いま一番気になっているのはどれですか。** 「全部ぼんやり」でも大丈夫です。

**2. そもそも、何がきっかけでこれを知りたくなりましたか。**

2番を聞くのは、「認証まわりが分からない」の中身が人によってかなり違うからです。たとえば——

- ログイン後になぜかログイン画面に戻される、という現象を追っている
- `sessions.ts` と `jwt.ts` が両方あるのが分からない（なぜ2つ要るのか）
- `userMiddleware` がいつ呼ばれるのかピンと来ない
- Issue のどれかに着手する前の下調べ

どれに近いか（あるいは全然別か）が分かると、案内する場所を1つに絞れます。
