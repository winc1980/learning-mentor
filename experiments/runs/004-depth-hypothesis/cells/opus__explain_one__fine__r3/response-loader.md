`app/lib/plain-date.ts` を読みました。まず全体像から。

## 一言で言うと

**「年・月・日だけを持つ日付」を表す自前の型**です。標準の `Date` の代わりに使うためのものです。

## なぜ自前で作るのか（ここが一番大事な部分）

JavaScript の `Date` は、実体としては「1970年からのミリ秒数」です。つまり **時刻とタイムゾーンが必ずくっついてきます**。

そうすると「2026年9月7日」というカレンダー上の1日を表したいだけなのに、

- `new Date("2026-09-07")` は UTC の 0時 と解釈される → 日本時間に直すと 9月7日 9時
- ここから `getDate()` すると環境によって 6日 になったり 7日 になったりする
- 「同じ日か？」を比較したいのに、時刻が違うと別物扱いになる

といった事故が起きます。ライブの開催日や応募可能日のような「日付そのもの」を扱うアプリでは、これがバグの温床になります。

そこで **時刻とタイムゾーンの概念を最初から持たない型** を用意する、というのがこのファイルの目的です。実際 `app/domain/entities/live-day.ts` など11ファイルで使われていて、このアプリの「日付」の共通語になっています。

（余談ですが、これは JS の標準仕様として `Temporal.PlainDate` が提案されている領域で、`PlainDate` という名前はそこから来ています。「Plain = 素の、タイムゾーンが付いていない」という意味です。）

## 中身のパーツは3つ

1. **`constructor`** — 月は1〜12、日は1〜31でなければ例外を投げる。つまり**不正な値のインスタンスは存在できない**ようにしている
2. **`static serde`** — `"2026/9/7"` という文字列との相互変換ルール
3. **`static now()`** — 今日の日付を作る（`getMonth()` が0始まりなので `+1` している）
