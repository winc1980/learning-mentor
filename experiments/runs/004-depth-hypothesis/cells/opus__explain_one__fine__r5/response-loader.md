`app/lib/plain-date.ts` を読みました。まず全体像から。

## 一言でいうと

**「時刻もタイムゾーンも持たない、年月日だけの日付」を表す自前の型**です。それに加えて、文字列との相互変換と、バリデーションがセットになっています。

## 中身は3つの役割に分かれています

**1. 値の入れ物 + 不正値の門番（`constructor`）**
`year` / `month` / `day` の3つを持つだけ。ただし作る瞬間に月が1〜12か、日が1〜31かを検査して、外れていれば例外を投げます。つまり **「PlainDate 型の値が存在する = 最低限の検査は通っている」** という状態を保証しています。

**2. 文字列との変換（`static serde`）**
- `serialize`: `PlainDate` → `"2026/9/7"` のような文字列
- `deserialize`: `"2026/9/7"` → `PlainDate`（正規表現でマッチしなければ例外）

`Serde` は `app/lib/serde.ts` にある共通インターフェースで、「シリアライズ/デシリアライズの組」を型として定義したものです（Rust の serde に由来する名前）。DB やフォームの値は文字列で出入りするので、その境界での変換をこの1箇所に集めている、という設計です。

**3. 今日の日付を作る（`static now`）**
JS の `Date` から年月日だけを取り出して `PlainDate` にします。`getMonth()` が 0 始まり（1月が 0）なので `+ 1` しています。

## なぜ標準の `Date` を使わないのか

ここがこのファイルの存在理由です。JS の `Date` は「年月日」ではなく **「UTC 基準のある一瞬（タイムスタンプ）」** を表す型です。そのため：

- 時刻成分が必ず付いてくる。「7日」同士を比較したいのに、9:00 と 15:00 で不一致になる
- タイムゾーン次第で日付がズレる。同じ瞬間が日本では 7日、UTC では 6日
- 「ライブの開催日」のような、そもそも時刻の概念がない値を表すのに過剰

`grep` すると `live-day.ts` や `availability.tsx` など、日程・空き日を扱う箇所で使われています。まさに「時刻を持たない日付」が欲しい領域ですね。
