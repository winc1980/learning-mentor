`app/lib/hash.ts` を読みました。3行目の `10` は、6行目の `bcrypt.hash(password, SALT_ROUNDS)` の第2引数として渡されている値ですね。

## まず、この 10 が何の数か

**「ハッシュ計算を何回繰り返すか」を決める数**です。しかも **10回ではなく、2の10乗 = 1024回**です。

`10` → 1024回
`11` → 2048回
`12` → 4096回

1増やすと計算量が倍になります。だから「10 という回数」ではなく「10 という**目盛り**」だと思ってください。bcrypt ではこれを **コスト係数（cost factor）** と呼びます。

## 名前がちょっと紛らわしい

変数名が `SALT_ROUNDS` なので「salt を10個作る？」「salt の長さ？」と読めてしまうのですが、**salt の個数でも長さでもありません**。salt（ハッシュに混ぜるランダムな値）は bcrypt が勝手に1つ生成してくれるので、この数字とは無関係です。

この名前は bcrypt の README がそう書いているので広まっただけで、実体はさっきの「繰り返し回数の目盛り」です。混乱するのが自然な箇所だと思います。

パスワードをハッシュ化して保存するのは、何のためだと思いますか？ 近いものを選ぶ形でも大丈夫です。

- **A**: パスワードを暗号化して、必要なときに元に戻して使うため
- **B**: DB が盗まれても、元のパスワードが分からないようにするため
- **C**: パスワードを短く固定長にして、DB の容量を節約するため
- **D**: 分からない

「分からない」も普通に回答として扱うので、遠慮なくどうぞ。
