`app/lib/plain-date.ts` を読みました。あわせて、そこから import されている `app/lib/serde.ts` も見ています。

## 一言で言うと

**「時刻を持たない、日付だけの値」を表すための自前の型**です。

JavaScript 標準の `Date` は、名前に反して「日付」ではなく **ある瞬間の時刻**（時・分・秒・ミリ秒、それにタイムゾーンの解釈）を持っています。だから「締切は9月7日」「誕生日は4月1日」のような、時刻が本質的に無いものを `Date` で扱うと、時差やゼロ時刻の扱いでズレが出ます。

このファイルはそれを避けるために、`year` / `month` / `day` という **数値3つしか持たない**クラスを定義しています。

## ファイルの中身は大きく3ブロック

1. **`PlainDateLike` 型と `PlainDate` クラス本体** — 年・月・日を保持する。コンストラクタで月が1〜12、日が1〜31かをチェックして、外れていたら例外を投げる
2. **`static serde`** — `PlainDate` ⇄ 文字列（`"2026/9/7"` のような形）の相互変換。`serde.ts` の `Serde` インターフェースに沿った形にまとめられている
3. **`static now()`** — 標準の `Date` から「今日の日付」を取り出して `PlainDate` を作る

ここから先、どこを深掘りするか決めたいので、1つだけ教えてください。**答えやすいところで大丈夫です。**

このコードで **一番「なんでこう書いてあるんだろう」と思った箇所**はどこですか？ 候補を挙げると：

- **A**: `static serde = { ... }` という書き方（なぜクラスの中にオブジェクトが置いてあるのか）
- **B**: `Serde<PlainDate, string>` の `<>` の部分
- **C**: `PlainDateLike` 型と `PlainDate` クラスが両方あること
- **D**: `date.getMonth() + 1` の `+ 1`
- **E**: そもそも標準の `Date` を使わない理由のところ

記号だけで構いませんし、「全部ぼんやり」でも大丈夫です。
