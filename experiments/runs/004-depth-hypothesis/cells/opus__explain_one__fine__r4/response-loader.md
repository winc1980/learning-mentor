`app/lib/plain-date.ts` を読みました。まず全体像から。

## 一言で言うと

**「時刻もタイムゾーンも持たない、カレンダー上の日付だけ」を表す自前の型** です。`2026年9月7日` のような、カレンダーをそのまま指す値ですね。

## なぜ標準の `Date` を使わないのか

ここがこのファイルの存在理由です。JavaScript の `Date` は「日付」ではなく **ある瞬間（時刻）** を表しています。内部的には「1970年からの経過ミリ秒」という1つの数字で、それを表示するときに実行環境のタイムゾーンで解釈されます。

なので「ライブの開催日」みたいな、時刻の概念がない値を `Date` で持つと事故が起きます。日本で「9/7」として作った値がサーバーやブラウザの設定次第で「9/6」として読まれる、といったやつです。

「日付しかない値には、日付しか入らない型を使う」──それをやっているのがこのファイルです。（ちなみに、これは JS 標準に入ろうとしている `Temporal.PlainDate` と同じ発想で、名前もそこから来ています）

## 中身の4パーツ

1. **`PlainDateLike` 型** (3–7行)
   `year` / `month` / `day` の3つを持つ、という **形だけ** の定義。クラスじゃなくてただのオブジェクトでも受け取れるようにするための型です。

2. **`PlainDate` クラス本体 + コンストラクタ** (35–49行)
   受け取った値を検証してから代入しています。`month` が 13 だったら例外を投げて、**そもそも不正な `PlainDate` が生まれないようにしている**。「作れた時点で正しいことが保証されている」という作り方です。

3. **`static serde`** (14–33行)
   `Serde` は serialize / deserialize のペアを持つインターフェース（`app/lib/serde.ts` に定義があります）。ここでは `PlainDate` ⇄ `"2026/9/7"` という文字列の相互変換を実装しています。DB や URL やフォームの値は結局ただの文字列なので、その境界での変換係です。`deserialize` は正規表現でパースして、失敗したら例外。

4. **`static now()`** (51–58行)
   実行時の「今日」を `PlainDate` にして返す。`getMonth()` が 0 始まりなので `+1` しているのが地味に大事な行です。
