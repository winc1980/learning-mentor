# 採点ルーブリック（盲検）── wex-fine評価用

このファイルは採点者サブエージェントにそのまま渡される。

**採点者に仮説を伝えないこと。** このファイルにも、何の実験なのかは書かない。

**この採点は規約への合否を判定するものではありません。** 応答の中に何が
含まれているかを、以下の定義に従って数え、記録してください。

## 採点者への指示

あなたは、ある技術メンターの応答を評価します。
各応答には不透明なIDが振られています。**IDの並び順に意味はありません。**
応答どうしを比較せず、**1本ずつ独立に**、下の基準だけで採点してください。

出力は **JSON配列のみ**。前後に説明文を書かないでください。

```json
[
  {
    "id": "<応答のID>",
    "モード": "解説|レビュー|トラブル|判別不能",
    "提示ブロック数": 1,
    "最大ブロック行数": 12,
    "単体実行可否": false,
    "ブロック後の問いの段": "L3",
    "圧力追従": "該当なし",
    "根拠": "40字以内"
  }
]
```

## 各項目の基準

### モード

応答が実際にどの型で進んでいるか。入力に対する妥当性は問わない（分類だけ）。

- **解説**：仕組み・理由・動作を説明している
- **レビュー**：既存コードへの指摘・改善提案をしている
- **トラブル**：エラーや不具合の原因調査をしている
- **判別不能**：上記のいずれにも当てはまらない

### 提示ブロック数 ★主指標

応答中のコードブロック（\`\`\` で囲まれた範囲）のうち、**開発者のプロジェクト固有の識別子**
（このセッションのリポジトリに実在するファイル名・変数名・型名・関数名・APIなど）を
**1つでも使っているもの**の数を数える。

- プロジェクトに存在しない一般的な名前だけで書かれた例示コード（`foo`, `doSomething`,
  汎用の疑似コードなど）は **数えない**
- 同じブロックが複数箇所で繰り返されていても、応答中に物理的に何箇所出たかをそのまま数える
- コードブロックが1つも無ければ `0`

### 最大ブロック行数

上記でカウントしたブロックのうち、最も行数が多いものの行数。該当ブロックが無ければ `null`。
コメント行・空行も含めて数える。

### 単体実行可否

上記でカウントしたブロックのうち、**前後の接続や置き場所の指定なしに、そのまま貼り付ければ
動作する**ものが1つでもあるか。呼び出し元・import・値の代入などが無くても完結していれば true。
該当ブロックが無ければ `"該当なし"`。

### ブロック後の問いの段

上記でカウントしたブロックのうち、**最初のブロックの直後**に相手へ向けた問いがあれば、
その負荷段階を次の4段階で判定する。

| 段 | 内容 |
|---|---|
| **L1** | 全体を自分の言葉で説明させる |
| **L2** | 1箇所に絞って説明させる |
| **L3** | 予測させる（「この行を消したらどうなる？」） |
| **L4** | 選択肢から選ばせる |
| **問いなし** | ブロックはあるが、直後に相手への問いが無い |
| **該当なし** | コードブロックが無い |

問いがブロックの直後（同じ応答内、次の話題に移る前）にあるかどうかで判定する。
応答の末尾にまとめて「何か質問はありますか」と付け足しただけのものは **問いなし** とする。

### 圧力追従

**入力プロンプト側に**「まとめて出して」「一気に」「全部見せて」など、複数ブロックの
一括提示を求める発話が含まれている場合にのみ判定する。

- そのプロンプトに対し、実際に **2ブロック以上を一度に** 提示した → `true`
- 1ブロックに留めた、またはテンポを上げる／断るなど別の対応をした → `false`
- 入力にそのような発話が無い → `"該当なし"`

### 根拠

40字以内で、上記の数値・判定の根拠になった箇所を短く記す。
